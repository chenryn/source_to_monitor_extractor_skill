# 输出格式规范（9 章）

最终交付物是一份「源码可观测性分析方案」。固定结构，用表格，不写散文。

章节结构适用于各类项目；示例里的指标名、日志模板、阈值均为占位符，**必须替换为本项目提取结果里的真实值**。项目画像（第 1 章）决定后面各章该关注什么，不可省略。

---

## 第 4 章：信号仲裁表（核心章节）

**这一章是整份方案的价值所在**——它把「要监控什么」和「用什么监控」对应起来。

```markdown
## 4. 信号仲裁

| # | 监控需求 | 归属平面 | 现有信号 | 源码位置 | 结论 |
|---|---------|---------|---------|---------|------|
| 1 | 服务/作业是否活着 | 日志 | "<就绪或完成日志模板>" | ... | 已覆盖（存在性告警） |
| 2 | <处理> 延迟分位 | 指标 | <duration_histogram> | <file:line> | 已覆盖 |
| 3 | 失败原因 | 日志 | <ERROR 类模板> | ... | 已覆盖（需白名单） |
| 4 | 一次处理慢在哪一段 | 链路 / 属性 / 指标标签 | <span 或分段记录> | ... | 部分覆盖 |
| 5 | <平台/硬件层指标> | 指标 | 无 | — | **真缺口**：需接外部 exporter |

### 4.1 三平面检查记录（下「缺口」结论的必要条件）

| 平面 | 已检查内容 | 结果 |
|------|-----------|------|
| 日志 | 检索 N 条埋点，关键词：... | 无相关埋点 |
| 指标 | 检索 M 个指标名，关键词：... | 无相关定义 |
| 链路 | 检索 K 个 span | 无相关 span |
```

**硬要求**：没有 4.1 的检查记录，不允许在 4 或第 7 章写「缺少 X」。

## 第 8 章：版本迭代方法

```markdown
## 8. 版本迭代

### 8.1 标准流程

（三个提取脚本 + diff_signals.py 的命令）

### 8.2 变化处理矩阵

| 变化类型 | 对监控的影响 | 动作 |
|---------|-------------|------|
| 新增 ERROR 日志 | 可能有新的故障模式 | 评估新增 L2 告警 |
| 新增指标 | 新的可观测能力 | 评估新增 L1 告警 |
| 删除指标 | 已有告警会静默失效 | **必须下线对应告警** |
| 指标标签变更 | PromQL 静默失效 | 更新查询和看板 |
| 桶边界变更 | 分位精度变化 | 重新校准阈值 |

### 8.3 diff 的局限性

- 按「文件名 + 模板」模糊匹配，忽略行号偏移（这是刻意的）
- 同文件内模板完全相同的多条日志会被折叠 → 计数是近似值
```

## 第 9 章：局限性说明

```markdown
## 9. 局限性

1. **阈值为候选值**：需结合 SLO、压测基线、线上历史校准。

2. **源码常量 ≠ 告警阈值**：`timeout=5s` 是业务配置，告警可能设在 P95 > 2s。

3. **提取覆盖率不是 100%**：
   - 指标：自定义 DSL、动态命名（`name=f"ns:{x}"`）无法静态解析
   - 日志：拼接构造的消息、间接调用（封装函数）无法提取模板
   - 明确列出「需人工确认」清单，不要把提取遗漏当成不存在

4. **静态分析看不到运行时**：
   - 条件定义（`if` 包裹）的指标可能默认不注册
   - trace 通常默认关闭，需确认配置
   - 采样率、白名单、限流等运行时行为需结合配置

5. **未覆盖的场景**：源码之外的资源/平台层指标（需外部 exporter 或宿主机采集）、业务语义判断（需真实流量验证）。

6. **脚本能力边界**：列出未覆盖的语言/框架、人工提取的部分及其覆盖率未知的影响；脚本输出为 0 不得直接写成「该平面无信号」。
```

## 输出硬约束

1. 第 1 章项目画像**必须有**（运行形态、语言、技术栈、暴露方式、默认开关），它决定需求清单
2. 第 4 章信号仲裁表**必须有**，且每条结论都要能溯源
3. 所有阈值标注「候选，待校准」
4. 每条告警溯源到文件+行号
5. 禁止编造源码中不存在的信号，禁止套用样例里的指标名/阈值/维度
6. 「缺少 X」必须附三平面检查记录
7. 第 9 章必须有，防止方案被误当成定稿
